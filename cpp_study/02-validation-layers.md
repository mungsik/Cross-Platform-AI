## 1. constexpr

③ const char* (타입)

char: 글자 하나

char는 글자 하나(1바이트) 를 담는 기본 타입입니다.
char c = 'A';   // 글자 하나. 작은따옴표

char*: 글자가 있는 곳의 주소

타입 뒤에 *를 붙이면 "그 타입이 있는 곳을 가리키는 포인터" 가 됩니다.
char*  → char가 있는 곳의 주소
int*   → int가 있는 곳의 주소
vk::ApplicationInfo* → ApplicationInfo가 있는 곳의 주소

그런데 왜 이게 "문자열"이 될까?

C/C++에서 "VK_LAYER..." 같은 문자열은 메모리에 글자들이 한 줄로 쭉 이어져 저장되고, 맨 끝에 '\0'(널 문자) 가 붙습니다.

주소:   0x1000 0x1001 0x1002 0x1003 ...                  0x101B
내용:   [ V ]  [ K ]  [ _ ]  [ L ]  ... [ o ] [ n ]  [ \0 ]
         ↑                                              ↑
  validationLayer가 여기를 가리킴                    "여기서 끝"

char*는 첫 글자의 주소만 들고 있습니다. 읽는 쪽은 그 주소부터 한 글자씩 읽다가 '\0'을 만나면 멈춥니다. 그래서 길이 정보 없이도 문자열을 다룰 수 있습니다. 이것을 C 스타일 문자열이라고 합니다.

C++에는 더 편한 std::string도 있지만, Vulkan은 C API라서 const char*를 씁니다.

④ validationLayer: 변수 이름

⑤ "VK_LAYER_KHRONOS_validation": 값

Khronos가 만든 검증 레이어의 공식 이름입니다. 이 이름은 정해져 있는 것이라 오타가 나면 레이어를 찾지 못합니다. 이 서버에는 vulkan-validationlayers 패키지로 설치되어 있습니다.

② constexpr: 컴파일할 때 값이 정해짐

constant expression(상수 표현식)의 줄임말입니다. "이 값은 프로그램을 실행하기 전, 컴파일할 때 이미 확정된다"는 뜻입니다.

┌───────────┬────────────────────────────────────────────────────────┐
│           │                          의미                          │
├───────────┼────────────────────────────────────────────────────────┤
│ const     │ 한 번 정하면 바꿀 수 없음 (값은 실행 중에 정해져도 됨) │
├───────────┼────────────────────────────────────────────────────────┤
│ constexpr │ 바꿀 수 없음 + 컴파일할 때 값이 확정됨                 │
└───────────┴────────────────────────────────────────────────────────┘

레이어 이름은 실행할 때마다 달라질 일이 없는 고정 문자열이라 constexpr을 씁니다.

① static: 객체마다가 아니라 클래스에 하나만

클래스 안의 static 멤버는 객체마다 따로 만들어지지 않고, 클래스 전체에 하나만 존재합니다.

static 없는 멤버 (instance):        static 멤버 (validationLayer):
app1 ─ instance                     ComputeApplication
app2 ─ instance                       └ validationLayer  ← 하나를 모두가 공유
(객체마다 따로)

instance는 객체마다 따로 있어야 하지만, 레이어 이름은 모두 같은 값이니 하나만 있으면 됩니다. 그리고 C++ 규칙상 클래스 안에서 바로 값을 넣는 constexpr 멤버는 static이어야 합니다. 그래서 둘이 짝으로 붙어 다닙니다.

왜 굳이 상수로 만들까?

README의 설명대로 이 이름을 두 번 쓰기 때문입니다.
1. 레이어가 설치되어 있는지 검색할 때
2. 인스턴스를 만들 때 활성화할 때

문자열을 두 군데에 직접 쓰면 한 곳에서 오타가 나도 알아채기 어렵습니다. 상수 하나로 만들어 두면 이름을 한 곳에서만 관리할 수 있습니다.
