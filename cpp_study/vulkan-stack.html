온디바이스(기기 한 대 안에서 모델을 돌리는 상황)를 가정해서, 우리 C++ 코드와 Vulkan, 제조사 드라이버, GPU가 각각 어디에 있고 명령 하나가 어떤 길을 지나 결과가 되는지 그림으로 정리했습니다. 00~07장 객체 관계는 총정리, 디스크립터는 디스크립터 그림에 있습니다.

1. 기기 한 대 안의 층 구조

기기(노트북, 휴대폰, GCP 인스턴스) 하나를 위에서 아래로 자른 그림입니다. 제조사 칸을 네 개 그렸지만 한 기기에는 보통 하나만 실제로 꽂혀 있고, 로더는 꽂혀 있는 드라이버만 연결합니다. 우리 인스턴스에서는 NVIDIA 칸만 살아 있습니다.

위 두 층은 어느 기기든 같다

  • main.cpp 한 벌
  • add.spv 한 벌
  • 호출하는 함수 이름과 인자 형식
파이썬 비유: DB-API 규격(PEP 249)대로 cursor.execute()만 부르는 코드

아래 두 층은 기기마다 다르다

  • 드라이버 구현 (제조사 코드)
  • SPIR-V가 번역되는 기계어
  • 큐 패밀리 번호, 메모리 타입 번호, 한계값
파이썬 비유: psycopg2냐 sqlite3냐

로더가 가운데서 이어 준다

  • 앱은 드라이버 파일 이름을 모른다
  • 로더가 설치된 ICD 목록을 읽어 연결
  • GPU가 둘이면 03장 "장치 목록"에 둘 다 나옴
파이썬 비유: 어느 드라이버 모듈을 import할지 골라 주는 자리

2. 명령 하나의 여행: 벡터 덧셈이 결과가 되기까지

11장 a + b를 기준으로, 한 번 실행할 때 각 단계가 어느 층에서 일어나는지 가로줄(레인)로 나눴습니다. 확인하는 일은 전부 우리 코드 레인에 있고, 드라이버와 GPU 레인에는 "시키는 대로 한다"만 있습니다.

4. 이 기기에서 "안 되는" 명령은 어디서 걸리나

어느 단계에서 걸리느냐에 따라 결과가 세 갈래입니다. 깔끔한 에러는 가운데 갈래 하나뿐이라서, 왼쪽 갈래(코드가 미리 거름)로 가도록 짜는 것이 Vulkan 코드의 기본 습관입니다.

11장에서 CPU 기준값과 비교하고, VK_VALIDATION_VALIDATE_SYNC=1로 동기화 검증까지 켜서 "경고 없음"을 확인한 것이 C 갈래를 개발 중에 막는 장치입니다. 검증 레이어는 수식의 옳고 그름은 모르므로 기준값 비교가 따로 필요합니다.

5. 전체를 파이썬 한 덩어리로

# 1~2. 물어보고 고르기 (우리 코드의 몫. Vulkan이 대신 안 해 줌)
devices = vk.list_devices()                        # 로더가 설치된 드라이버에게 물어봄
gpu = next(d for d in devices if d.has_compute_queue)   # 없으면 StopIteration → A 갈래
mem_type = next(t for t in gpu.memory_types if t.host_visible)

# 3. 만들기 (드라이버가 실제 자원을 잡고 SPIR-V를 기계어로 컴파일)
device = gpu.create_device(queue_family=gpu.compute_family)   # 없는 기능 요구 → B 갈래(예외)
shader = device.create_shader_module(open("add.spv", "rb").read())
a, b, out = (device.create_buffer(32, mem_type) for _ in range(3))

# 4~5. 기록하고 제출 (내용 검사 없음 → 틀리면 C 갈래)
cmd = device.record(lambda c: c.dispatch(shader, [a, b, out], workgroups=1))
fence = device.queue.submit(cmd)        # queue.put(job)과 같은 느낌, 바로 돌아옴

# 6~7. GPU 실행 → 기다리고 읽기
fence.wait()                            # job.result()
assert out.read() == [x + y for x, y in zip(a.read(), b.read())]   # 검증 레이어는 수식을 모름

같은 이 코드를 AMD나 휴대폰에서 돌리면 바뀌는 것은 list_devices()가 돌려주는 내용과, 드라이버가 뒤에서 하는 컴파일뿐입니다. 우리 쪽 줄은 한 줄도 안 바뀝니다.
