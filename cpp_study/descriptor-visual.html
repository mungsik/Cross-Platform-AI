2. 헷갈리는 "개수" 여섯 개

06·07장에는 이름이 비슷한 개수 필드가 많습니다. 무엇을 세는지가 다릅니다.

bindingCount = 3

06장 · DescriptorSetLayoutCreateInfo

layout 안 binding 수. binding 0, 1, 2.

bindings[i].descriptorCount = 1

06장 · DescriptorSetLayoutBinding

binding 하나에 들어가는 descriptor 수. 버퍼 안 원소 수(8)가 아닙니다.

maxSets = 1

07장 · DescriptorPoolCreateInfo

pool에서 할당할 수 있는 descriptor set의 최대 수.

poolSize.descriptorCount = 3

07장 · DescriptorPoolSize

pool 전체의 storage descriptor 수. set 1개 × binding 3개 × binding당 1개 = 3.

descriptorSetCount = 1

07장 · DescriptorSetAllocateInfo

이번 호출로 할당할 set 수. pSetLayouts에 이 수만큼 layout을 줌.

writes[i].descriptorCount = 1

07장 · WriteDescriptorSet

이번 write로 binding 하나에 써 넣을 descriptor 수. 06장 binding의 descriptorCount와 맞춤.

같은 이름 descriptorCount가 세 번 나옵니다. binding당(06 layout), pool 전체(07 pool), 이번 write 양(07 write)으로 구분하세요. pool 전체 3 = binding당 1 × binding 3 × set 1.

3. 코드의 &와 *가 가리키는 것

복습 목록에 있던 세 줄입니다. 이름부터 정리하면 &(ampersand, 앰퍼샌드)를 값 앞에 쓰면 address-of operator(주소 연산자), *(asterisk, 애스터리스크)를 값 앞에 쓰면 dereference(역참조), 즉 "안쪽을 꺼내라"입니다.

handle만 꺼내 bufferInfo에 넣음. 필드 타입이 handle인 vk::Buffer이기 때문 allocInfo.pSetLayouts = &layout; layout (지역 변수) 주소 0x7ffd…10 에 있음 pSetLayouts 0x7ffd…10 & layout 값을 복사하지 않고 있는 곳(주소)을 알려 줌. p = pointer. "여기서부터 descriptorSetCount(1)개 읽어" writes[i].pBufferInfo = &bufferInfos[i]; [0] [1] [2] writes[1] .pBufferInfo i번 write는 bufferInfos[i]의 주소를 가리킴. 그래서 bufferInfos 배열이 update가 끝날 때까지 살아 있어야 함

4. 전체를 파이썬 한 덩어리로

# 05장: 버퍼 = 실제 데이터 통
inputA, inputB, output = Buffer(32), Buffer(32), Buffer(32)

# 06장: descriptor set layout (binding 번호와 descriptor type만, buffer 이름 없음)
layout = {0: "storage", 1: "storage", 2: "storage"}

# 07장: descriptor pool (maxSets 1, storage descriptor 3개)
pool = Pool(max_sets=1, storage=3)

# 07장: layout으로 descriptor set 1개 할당 (allocate)
descriptor_set = pool.allocate(layout)        # {0: None, 1: None, 2: None}

# 07장: binding마다 descriptor 갱신 (update: 데이터 복사가 아니라 buffer 참조만)
descriptor_set[0] = (inputA, 0, 32)          # (버퍼, offset, range)
descriptor_set[1] = (inputB, 0, 32)
descriptor_set[2] = (output, 0, 32)

# 08장~: 셰이더는 set·binding 번호로만 접근
def add(s, i): s[2][i] = s[0][i] + s[1][i]
왜 layout과 set을 나눌까요? layout이 같으면 buffer만 다른 descriptor set을 여러 개 만들 수 있습니다. 파이썬 함수의 시그니처(layout)는 그대로 두고 인자(set)만 바꿔 호출하는 것과 같습니다. 09장 파이프라인은 이 layout(시그니처)을 보고 만들어집니다.
